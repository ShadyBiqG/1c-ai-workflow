# Происхождение решений workflow

Это оценка архитектурного влияния, а не процент буквального копирования кода. PowerShell state machine и скрипты этого проекта написаны отдельно; дословное заимствование строк не использовалось.

Условная оценка влияния на текущий дизайн:

- около 30% — `1c-feature-dev`: адаптивная сложность, артефакты по фазам, передача контекста агентам, возможность возобновления и ранняя проверка плана;
- около 35% — `AI_tools_for_project`: persisted state machine, evidence, отделение ролей, управляемый REVIEW и явные approval-границы;
- около 35% — решения `1c-ai-workflow`: единый Manager для пользователя, обязательный test-plan и VERIFY, DAG work items, безопасная параллельность, provider-neutral REVIEW и отсутствие обязательной привязки к Конфигуратору/EDT.

Проценты приблизительны: многие инженерные идеи являются общими и пересекаются между источниками. Для аудита полезнее следующая матрица.

| Решение | Основное влияние | Реализация здесь |
|---|---|---|
| Адаптация процесса по сложности | `1c-feature-dev` | `small` / `medium` / `large` / `critical` |
| Артефакты и продолжение в новом чате | оба примера | `memory.md`, `journal.json`, план, результаты и evidence |
| Persisted state machine | `AI_tools_for_project` | `state.json` и атомарные переходы |
| Approval, связанный с неизменным сценарием | `AI_tools_for_project` | SHA-256 плановых артефактов |
| Обязательное тестирование | собственное усиление | обязательный `test-plan.md` и VERIFY check `tests` |
| Декомпозиция и параллельные Workers | собственное усиление | проверяемый DAG, зависимости и `parallel_safe` |
| Архитектурный gate до реализации | развитие идеи раннего review | отдельные Architect и Architecture Reviewer, независимость и привязка к SHA-256 |
| Независимость от конкретной среды 1С и AI provider | собственное требование | конфигурируемые adapters и REVIEW |

Папка `AI_tools_for_project` используется только для чтения и сравнения; этот workflow её не дорабатывает.
