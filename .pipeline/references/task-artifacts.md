# Артефакты и память задачи

Каждая задача хранится в `.pipeline/tasks/<task-id>/`. Файлы внутри папки являются источником истины для Manager и агентов, включая продолжение работы в новом чате.

| Артефакт | Назначение |
|---|---|
| `request.md` | Исходный запрос пользователя без пересказа |
| `state.json` | Текущее состояние и история переходов state machine |
| `memory.md` | Краткий актуальный контекст: факты, решения, риски, открытые вопросы и следующий шаг |
| `journal.json` | Хронологический журнал этапов, решений, вопросов, подтверждений и evidence |
| `architecture.md` | Архитектурное решение отдельного Architect для сложностей из `manager.architecture_for` |
| `architecture.json` | Автор и SHA-256 актуальной архитектуры |
| `architecture-review.json` | Вердикт независимого Architecture Reviewer для сложностей из `manager.architecture_review_for` и проверенный SHA-256 |
| `architecture-reviews/*.md` | Evidence всех итераций архитектурного ревью |
| `decomposition.json` | Утверждённая структура work items и зависимостей |
| `work-items.json` | Текущие статусы, назначенные агенты и ссылки на результаты |
| `plan.md` | Самодостаточный план реализации и архитектурные ограничения; сохраняется до ожидания approval |
| `test-plan.md` | Обязательные сценарии и команды проверки; сохраняется до ожидания approval |
| `plan-approval.json` | Подтверждение пользователя для требуемых уровней сложности, связанное с SHA-256 плановых файлов |
| `work-results/<item-id>.md` | Что сделал агент, изменённые файлы, решения, тесты и evidence |
| `verify-evidence*.json` | Результаты каждой попытки обязательного VERIFY |
| `review-evidence-*` | Вердикт и основания независимого REVIEW, если он включён |
| `deploy-scenario.md` | Одобряемый пользователем сценарий применения в базе |
| `deploy-approval.json` | Подтверждение, связанное с SHA-256 сценария |
| `deploy-evidence-*.md` | Фактические команды, результаты, проверки и откат Deploy |
| `summary.md` | Итог, ключевые решения, проверки, изменённые файлы, ограничения и продолжение |

## Правила журнала решений

Manager фиксирует существенное решение как `decision`: выбранный вариант, основание, важные отклонённые альтернативы, риски и ссылку на evidence. Подтверждения пользователя фиксируются как `approval`. Обычные технические действия объединяются в содержательные этапы, чтобы журнал не превращался в копию терминального вывода.

## Использование памяти

`memory.md` — это проектная долговременная память конкретной задачи, а не скрытая память модели. Manager обновляет её после архитектуры и её ревью, PLAN, каждого завершённого work item, VERIFY/REVIEW и перед завершением чата. В новый чат передаётся путь к папке задачи; Manager читает сначала `state.json` и `memory.md`, затем журнал и только относящиеся к текущему этапу evidence.

Артефакты по умолчанию сохраняются локально и исключены из Git через `.gitignore`. Для командной или архивной истории папку выбранной задачи можно добавить в Git осознанно с `git add -f`, предварительно проверив её на секреты и локальные данные.
