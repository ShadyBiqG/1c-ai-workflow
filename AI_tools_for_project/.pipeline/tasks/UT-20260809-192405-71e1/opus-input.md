# Second opinion: план розового оформления формы реализации

## Роль и ограничения

Проверь проект плана, не выполняя реализацию. Задача относится к основной конфигурации UT 11.5.19.74, платформа 1С 8.5.1.1302. Разрешено менять только основную форму документа `РеализацияТоваровУслуг`; расширение не используется, модуль формы и другие объекты не меняются. Work не загружает изменения в файловую базу.

## Установленные факты

- `Documents/РеализацияТоваровУслуг.xml:239` задаёт `DefaultObjectForm` как `Document.РеализацияТоваровУслуг.Form.ФормаДокумента`.
- Целевой файл: `Documents/РеализацияТоваровУслуг/Forms/ФормаДокумента/Ext/Form.xml`.
- `form-info` сообщает, что форма снята с поддержки, а значит точечные изменения допустимы.
- В форме уже есть два семантических `BackColor`; их нельзя менять.
- Верхнеуровневые страницы: `ГруппаОсновное`, `ГруппаТовары`, `СтраницаДоставка`, `ГруппаДополнительно`.
- Верхнеуровневые группы: `ГруппаСтатус`, `ГруппаПодвал`, `ГруппаСчетФактураИСостояние`.
- Основная кнопка: `ФормаПровестиИЗакрыть`.
- В репозитории есть примеры literal-цветов вида `<BackColor>#FFF0F0</BackColor>` для `UsualGroup`, `<BackColor>#FEFEFE</BackColor>` для `Page` и `<BackColor>#FFE100</BackColor>` для `Button`.

## Рассмотренные подходы

1. **Рекомендуемый:** статически задать цвета только у крупных контейнеров и основной кнопки в одном `Form.xml`. Это детерминированно, не затрагивает поведение и остаётся в заданном объёме.
2. Программно окрашивать элементы при открытии формы. Отклонено: потребует изменения модуля формы, добавит поведенческий код и риск сброса цветов.
3. Добавить общие элементы стиля. Отклонено: выйдет за пределы одной формы и затронет другие метаданные.

## Проект плана

### Изменение

Точечно добавить XML-свойства, не перестраивая форму и не меняя существующие ID:

- `ГруппаОсновное`, `ГруппаТовары`, `СтраницаДоставка`, `ГруппаДополнительно`: `<BackColor>#FFF0F5</BackColor>`;
- `ГруппаСтатус`, `ГруппаПодвал`, `ГруппаСчетФактураИСостояние`: `<BackColor>#F8BBD0</BackColor>`;
- `ФормаПровестиИЗакрыть`: `<BackColor>#EC407A</BackColor>` и `<TextColor>#FFFFFF</TextColor>`.

Существующие `BackColor` внутри формы, включая `style:ЦветФонаВыделения` и `style:ИтогиФон`, оставить без изменений. Не менять `Module.bsl`, форму-обёртку `.xml`, метаданные документа, другие формы, расширения и StyleItems.

### Проверки до и после

1. До правки выполнить XML-assertion по восьми именованным элементам: он должен завершиться ошибкой, потому что палитра ещё не задана.
2. После правки повторить assertion: все восемь элементов должны существовать; у каждого должен быть ровно один `BackColor` с ожидаемым значением; у основной кнопки должен быть `TextColor=#FFFFFF`.
3. Выполнить `form-validate.ps1 -Detailed` для целевого `Form.xml`; ожидается `PASS`/нулевой код.
4. Выполнить `form-info.ps1` и убедиться, что форма по-прежнему распознаётся как `ФормаДокумента` объекта `РеализацияТоваровУслуг`.
5. Проверить `git diff --check` и scoped diff: реализация меняет только целевой `Form.xml`; изменения состоят только из девяти добавленных цветовых XML-свойств, существующие цветовые свойства не изменены.
6. Work не запускает и не обновляет файловую базу. После отдельного одобренного Deploy вручную открыть новый и существующий документ в основной форме и проверить четыре вкладки, статус, подвал и основную кнопку; операции записи/проведения должны вести себя как до изменения.

### Критерии приёмки

- Основная форма на всех четырёх верхнеуровневых вкладках имеет светло-розовый фон, статус/подвал оформлены розовым акцентом, кнопка «Провести и закрыть» — более насыщенным розовым с читаемым белым текстом.
- Все поля, таблицы, команды, обработчики, видимость, доступность и порядок элементов сохранены.
- Изменён только целевой `Form.xml`; модуль формы и прочие объекты не меняются.
- Структурная валидация и статические проверки проходят; визуальный результат подтверждается только после отдельного одобренного Deploy.

## Что проверить

Дай краткую, но строгую вторую оценку:

1. Поддерживаются ли выбранные свойства указанными типами элементов в XML управляемой формы и достаточен ли набор контейнеров для явно розового оформления?
2. Есть ли риск, что выбранная палитра нарушит читаемость или семантические цвета?
3. Достаточны ли проверки и критерии приёмки с учётом запрета Work на загрузку в базу?
4. Какие материальные пункты плана нужно изменить, убрать или добавить?

Ответ структурируй как: `verdict`, затем список материальных пунктов с категорией `accept`, `change` или `risk` и конкретным обоснованием.
